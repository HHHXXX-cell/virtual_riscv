## 1. 问题（可核事实，非推理）

- **F1｜原行**：`spec/01` §1.3「每拍吞吐」表发射行＝`6 μop（分 3 组：INT≤4、MEM≤2、BR≤1）`，参数列 `ISSUE_WIDTH`（行 71）。
  该表三行注（行 76~80）现文为：三项＝**选择器分组上限**；`MEM≤2`＝`AGU_NUM`2、`BR≤1`＝`BRU_NUM`1（与该组执行单元数一致）；
  `INT≤4` **≠** INT 组执行单元数 6；来源登记待裁＝`doc/process/ledger.json` R-205；末句＝「三组之和 7 > `ISSUE_WIDTH=6`，由选择器按年龄仲裁，见 `spec/05`」。
- **F2｜加总复算（`spec/00` §4.4 表内文字）**：INT 组可派发单元＝`ALU_NUM`3＋`SHIFT_NUM`1＋`MUL_NUM`1＋`DIV_NUM`1＝**6**；
  MEM 组＝`AGU_NUM`**2**；BR 组＝`BRU_NUM`**1**；三组单元数合计＝`N_EU_TOTAL`**9**＝3+1+1+1+1+2。
  `spec/00` §3 微架构图同源：`IQ_INT 24 ─► ALU×3 / SHIFTER / MUL / DIV`、`IQ_MEM 20 ─► AGU×2`、`IQ_BR 20 ─► BRU`。
- **F3｜活引用面（全库检索）**：`INT≤4`／`MEM≤2`／`BR≤1` 的现行活引用只有三处——`spec/01` §1.3（行 71／76／77／79）、
  `doc/verify/01` F-20、`doc/verify/02` VP-20（其余命中的是 `doc/review/*` 评审探针快照与台账，属历史记录）。
  `spec/00` §4 **无任何 4 相关的端口数／单元数**：`PRF_RD_PORTS`16＝12（发射级读＝`ISSUE_WIDTH`×2）＋4（**提交读**），该 4 与发射组无关。
  `spec/05` 全篇无这三项；其 §4 T-05-2 只登记「发射组内年龄仲裁的时序细则（同拍多就绪时的选择序与公平性）」为**待定项**。
- **F4｜缺陷性质**：本项不是「数值算错」，而是**「声明值与声明依据不闭合」＋「该量无定义」**（第三轮对抗性证伪 A 线的原判）。
  第一轮已把不成立的依据句（原写「是各组的读口与执行单元数上限」）更正，故本轮唯一的开口是：**这三项是哪个量、4 的依据在哪**。

## 3. 选定

**选定 (b)：`INT≤4`／`MEM≤2`／`BR≤1` ＝ 发射选择（`W` 拍）每拍可从该组选出的 μop 数上限（组选择口配额）。**

- **三条可判判据（交验证侧落点）**：
  - **J1**：任一拍，每组被选中的 μop 数 ≤ 该组配额（INT ≤ 4／MEM ≤ 2／BR ≤ 1）。
  - **J2**：任一拍，三组被选中数之和 ≤ `ISSUE_WIDTH`＝6（超配时由选择器按年龄仲裁，细则归 `spec/05` T-05-2）。
  - **J3**：本配额**不承诺**「该组执行单元全忙」——INT 组执行单元数＝6（F2）、发射级读口＝12＝6 发射口×2（F3，未按 4/2/1 分组）
    ⇒ 「配额 4」与「INT 组有 6 个单元/6 个发射口」**并存不矛盾**，二者是不同资源面。
- **生效范围**：口径与 J1~J3 即时生效（可直接写检查器与断言）；**数值 4/2/1 与「三组之和 7」零改动**。
- **值依据部分（不得记「已定」）**：4/2/1 的取值依据 = **无锚点** ⇒ 按红线 R20 降级为「登记＋预测＋回退点」：
  - **登记**：值依据归口 = `spec/05` T-05-2（发射组内年龄仲裁细则，**已登记待定**）＋ G1 评审 list ④段；`spec/01` §1.3 注的「登记待裁＝R-205」由本 ADR 承接。
  - **预测（可证伪）**：① 若该配额源于「该组执行单元数」，则 INT 行应为 6、三组之和应为 9（选择器溢出裕量 3）——与现文 4／7 相抵，
    且会削弱 A-1 ①「分组以仲裁复杂为代价」的取舍；② 若该配额是**独立的结构分区参数**（为选择器的端口/时序面封顶，A-2／A-4），
    则 4／7（溢出裕量 1）自洽。**现有锚点判不出孰是**。
  - **回退点／升级点**：见 §6（唯一机械动作）。
- **本 ADR 的「已定」边界**：只「已定」**口径**（这三项指哪个量、怎么判）；**未定**值依据。引用本 ADR 时不得表述为「4 的依据已定」。

## 4. 锚点

- **A-1（外部·一级依据，`D:\IC验证知识库\Verilog与CPU设计知识库\CPU卷\04-高性能超标量CPU精读.md`，源书《超标量微架构》第 5 章）**：
  - ① **p.211-213 发射队列结构三型**：**分组**＝「同类指令共享，R10000 三队列、Cortex-A77 整数/向量浮点/访存三组」——「灵活性与利用率更好，
    **代价是多端口仲裁复杂**」。⇒ 与本题同构（三组：INT/MEM/BR），且锚定「分组配额是为**仲裁/端口**面设置的取舍」，未必等于单元数。
  - ② **p.224-230 发射队列工作机制四步**：②「分发：**扫描队列选所有操作数就绪的最旧指令送空闲单元**」。
    ⇒ 每拍从一组送出多少，是「选择」这一步的宽度问题（本 ADR 命名的「组选择口配额」正落在此步）。
  - ③ **p.229-230、432-434**：**「唤醒-选择的 CAM 逻辑是乱序核心的成本中心」**——端口×容量乘积决定面积/时序。
    ⇒ 选择面是**可独立设计并封顶**的资源面（本项目 `spec/00` §4.4 `WAKE_BCAST_PORTS`＝6 同一代价族）。
- **A-2（本项目内锚，`spec/00` §4.4／§4.3／§5，表内文字）**：证明「选择/读口面」与「执行单元数」是两个独立资源面——
  `PRF_RD_PORTS`16＝`ISSUE_WIDTH`×2＝12（发射级读，6 发射口×2）+4（提交读）；§4.4 `OPND_READ_POLICY` ＝后读，依据列引
  【超】p.221-223、231-232（「队列条目只存编号（条目窄、读口少）」）；§5 D2 行引【超】p.221-223「**发射宽度 6 > 分发宽度 4**，
  后读总读口更少、队列条目更窄」。⇒ 6＞4 的存在本身说明「宽度/端口/配额」面与「单元数」面不同层。
  （同源机器判：`spec/00` §4.4 `params-invariants` 17 条表内自洽断言**不含本量**，故本项不会与该机判相抵。）
- **A-3（内锚，`spec/01` §1.3 上下文）**：三项并列写在「级＝**发射**」行、参数列 `ISSUE_WIDTH`；注末句自述「三组之和 7 > `ISSUE_WIDTH=6`，
  由选择器按年龄仲裁」⇒ 三项与其所在行同层，是**选择器**这一层的量，不是队列条目数（原句已自明）、不是单元数（F2）、不是读口数（A-2）。
- **A-4（外部·同 A-1，p.211-213 尾句＋p.231-232 趋势）**：「**分组队列＋后读操作数成主流**（兼顾**仲裁时序**、队列瘦身、省寄存器堆读口）」
  ⇒ 分组配额的设计动机是**仲裁时序**，与本题 §2 (a) 的「代价是跨组仲裁成为常态」判定同向。
- **无锚点声明（红线 R20）**：以上锚点只覆盖**口径**；`4/2/1` 的**取值依据**在本项目内与外锚均**无推导行**（F3）
  ⇒ 值依据部分按「登记＋预测＋回退点」成立，**不得**在引用时表述为「已定」。
