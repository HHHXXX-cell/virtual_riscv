**② 为什么不选"原版 Spike（不改源码）"**——**两条实测失败**（`rc=255`，log 在 `sim/run_iss129_upstream/`）：
- 带项目内存区域 ⇒ `devices at [1000, 5000) and [1000, 2000) overlap`（boot ROM 恒挂 `DEFAULT_RSTVEC=0x1000`，
  与项目代码窗**必然重叠**；`riscv/sim.cc:485 add_device(DEFAULT_RSTVEC, boot_rom)`）；
- 不带 `-m`（上游默认 `DRAM_BASE=0x8000_0000`）⇒ `Access exception … Memory address 0x1000 is invalid`
  （ELF 段落在 `0x1000`，那里只有**只读** boot ROM，`riscv/devices.h:37 rom_device_t::store` 写不进）。
两个常量**都不是** DTB 或命令行可覆盖（`DEFAULT_RSTVEC` 只用于 boot ROM 挂载；`DRAM_BASE` 只用于
`riscv/cfg.cc:44` 默认布局与 `spike_main/spike.cc:237` 的 `-m<size>` 旧式写法）⇒ **不改源码无路可走**。

**③ 为什么不选"按上游 link.ld 另出一份 Spike 版 ELF"**（ISS-129 原文的另一条路）：
`sw/tests/riscv-tests/env/p/link.ld` 把代码放 `0x8000_0000`、`tohost` 放 `0x8000_1000` ⇒ ① 破
`AGENTS.md` §3.4 坑 2「**一份镜像喂两边**」（两侧镜像漂移会伪装成 DUT bug）；② 两侧 `pc` 不同址，
逐条比对须做**地址归一化＝放宽**（红线 R6，须白名单＋逐次登记）⇒ **弃**。

**④ 纪律（与生成件同等待遇）**：
1. 任何 ISS-vs-ISS 结论**必须写明对手方＝ `project` 变体（改过的 oracle）**，不得写成"原版 Spike"；
2. 两侧不一致时**先核补丁本身**（`iss/tools/spike_oracles.json` 的四件套 md5 ＋ 本补丁件），再判"谁错"；
3. 改了补丁或重建 oracle ⇒ 必须同步更新指纹件（`spike_run.py` 会因 md5 不符**拒跑**，不会静默放行）；
4. `--preset upstream`（上游映射那份，原样保留）**只作留证/对照**——跑不了项目 ELF，不得用于任何判定。
