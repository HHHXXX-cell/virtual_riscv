### 1.2 FTQ 四规则（Q-006 `done_when` 要求的成文条款）

| # | 规则 | 条款 | 依据 |
|---|---|---|---|
| F1 | 读写指针 | `wptr` / `rptr` 各 5 bit = 4 bit 索引 ＋ 1 bit 回绕位；`wptr` 仅由分配推进（每写一项 +1），`rptr` 仅由出队推进（每出队一项 +1）；出队严格队头序，禁止乱序出队；一切跨回绕的大小比较用参数化谓词 `older_W(x, y)`（语义：x 比 y 老，当且仅当 `((y − x) mod 2^W) < 2^(W−1)`）——FTQ 取 W = 5：`older_5(x, y)`（当且仅当 `((y − x) mod 32) < 16`，**mod 32 / 半量 16**；BLK-5 处置）。**显式声明**：`spec/01` §3.19 规则 1 的 `older(e, f)` 定义为 `((f − e) mod 256) < 128`，系 `rob_id` **8 bit 专用**形式，**FTQ 不直接引用该式**；两者只共用同一参数化定义、W 各取实体回绕宽度（FTQ 5 bit，本条） | `spec/01` §1.1、§3.3；`older` 参数化形式＝§3.19 规则 1 按 W 归一推广（W = 5 代入；锚点类型＝可证伪算式）；指针推进与回绕式为推导句，锚点类型＝可证伪算式（§7-3） |
| F2 | 分配与释放 | 分配＝在 `wptr` 处写入项、置有效与 `ftq_id`，随后 `wptr` +1；**出队（读）不是释放**——释放条件＝「本块末条指令字节取全」（§2.3 B-2）且「**本块内各指令的起始槽**（walk 自块首槽起产出的每条指令起始槽的集合，含经 `xw_carry` 拼接产出的指令）**均已写入 IBUF 或已按 lane 粒度作废**」；**集合澄清（CL-6）**：该集合＝**块内各指令起始槽**（通常多条；与 §3.1 C1 的 walk 产出、§3.2 的"起始槽"同义），**不是块首单槽**——只认块首会使释放先于块内其余指令的 IBUF 落位，与 B-2 的"取全"判据及 §3.2 停工语义（未写成不得丢弃）相抵；作废来源＝冲刷（F4）与 err 截断（§3.1 C1/C2）两类；未取全而需跨窗续取时该项保持"在取"状态，其上下文在 `P5` 的 `xw_carry` 中 | `spec/01` §1.1（P2/P3）、§3.16 ②、§3.3（IBUF lane 语义）；释放条件为机制句（CL-6 澄清），锚点类型＝§3.16/§3.2 引用＋语义一致性论证（评审面） |
| F3 | 满/空判定 | 空：`wptr == rptr`（全 5 bit 相等）；满：`wptr[3:0] == rptr[3:0]` 且 `wptr[4] != rptr[4]`（同索引、异回绕位，可用满 16 项）；满在**分配拍前**组合判定，满时 `P2` 停写（BP 级反压）；空时 `P3` 不出队；两谓词互斥 | `spec/00` §4.2（`FTQ_ENTRIES` = 16）；`spec/01` §3.3（回绕位 = `ftq_id` 最高位）；互斥性为可证伪算式（§7-3） |
| F4 | 冲刷交互 | 重定向/恢复携带边界 `ftq_id`（＝发起指令所属项）；边界项**之后**的所有项作废（`older_5(x, boundary)` 为假且 x 非 boundary 的项；`older_5` 见 F1），`wptr` 回退至边界 +1、被作废项有效位当拍清零；`xw_carry` 随冲刷作废（§3.16 ③）；**冲刷优先于满/空与停工**，可无条件打断 `P5` 停工态；恢复点＝重定向目标 PC 作为新分配项的块首（不对已作废项重放）；边界项自身的保留/作废口径引用 `spec/01` 的冲刷定义，本篇不另规定 | `spec/01` §3.16 ③（冲刷/重定向作废）、§7（lane 粒度口径）；边界项处置＝引用句（对账表 T-08） |

不变式：

- **I3-1**：FTQ 的 `wptr` / `rptr` 只由「分配」与「出队」两种事件推进；任何停工/冲刷/重定向不改变指针推进规则本身（冲刷按 F4 回退 `wptr`）。空与满两谓词不同真。
- **I3-2**：FTQ 项在其释放条件（F2）满足前，其 `ftq_id` 值不得被重新分配给新项。

### 2.3 块布局限制（ISS-039 收口条款）

> 本节为 `doc/process/00` ISS-039 决策列（ADR-1，选 A：`xw_carry` 尾半字保持＋次窗拼接）交办 `spec/03` 的"块布局细则"落文；与 `spec/01` §3.16 的逐句对账见 §2.4。

- **B-1 块可起任意 2B 槽**：块首指令起始地址允许落在任意 2 字节槽（无奇偶槽限制）；块首槽 = 块起始 `pc[4:1]`，`win_base_pc[1:0]` 恒 00、不作定位键。**I3-3**：块首 `pc[0]` 恒 0，`pc[4:1]` 唯一确定块首槽（存在性与唯一性均为可证伪算式，§7-9；BLK-4 处置：原引 §7-5 系 nib/字节反例行、改引本行）。
- **B-2 fetch loop 终止 = 末条指令字节取全**：取指 loop 的终止判据是"末条指令的全部字节已到手"，不是 nib 计数完成、不是窗槽耗尽。收尾两情形：①末条指令完全落在当前窗内，本轮 walk 产出到它即止；②末条指令为槽 15 起的 32 位指令（或字节跨窗），必须经 `xw_carry` 与次窗槽 0 拼接后才算"取全"（`spec/01` §3.16 ②）。
- **B-3 "两窗内取全路径"的块字节跨度上界 66 B（限域；BLK-2 处置取①限域，不取②改名）**：术语——块跨度 = 末条指令末字节地址 − 块首字节地址 + 1。**适用域**：本上界只对"两窗内取全路径"成立——块首字节所在 32B 窗基址为 W 时，块的全部内容（含经 `xw_carry` 拼接的尾 2 B）在"W、W+32 两完整窗 + 第三窗 W+64 前 2 B"内取全，此时末条指令末字节地址 < W + 66。等号场景几何：块首在 W 偏移 0（槽 0）、块内容覆盖 W、W+32 两个完整窗（64 B）＋第三窗 W+64 的前 2 B（64 + 2 = 66）；该 2 B（W+64、W+65）在本适用域内只由 `xw_carry` 消费——它们是 **W+32 窗槽 15** 起的 32 位指令的尾 2 B：该槽地址 = (W+32) + 30 = **W+62**（**BLK-3/CL-2 更正**：槽 15 属 W+32 窗；原句"槽 15 地址 = 基址 + 30"未对基址限域，按字面读作 W+30 则末字节 W+33、与 W+65 恰差一窗，该读法已作废），该指令占字节 **W+62 至 W+65**、末字节 W+65 = W + 66 − 1。**限域边界**：`xw_carry` 拼接按 §3.16 ② 的 walk 语义发生（本窗槽 15 起 32 位指令装载 carry、次窗先产出拼接再自槽 1 续走）；**>66 B 块**（无分支长串型合法块——本章节片评审件构造的朴素续走 68 B、拼接续走 98 B 反例）**不在本上界覆盖范围**，其处置 ⇒ §4 待补 **T3-1**（与 `spec/04` 联片定稿）；闭合前实现不得以截断或静默丢弃处置。依据＝`doc/process/00` ISS-039 决策列的声明值（66 B）＋本篇几何复算（§7-2，限域后）。**更正路径（CL-2）**：基准件＝`doc/process/00` ISS-039 决策列原文（ADR-1 选 A）＋`spec/01` 现行文本（§1.1 P5 行「ISS-039 定案 A」、§3.16）；落点＝本篇 §2.3 行内更正注（涉接口/位宽者按篇首②回写 `spec/01` 接口升版）；批准人＝R0（经 R8/领队按规则 23 呈报，本篇不代行）。该读法尚未经评审轮核对（首片未评审，见 §6.1①）——原句"该读法经评审轮核对"已删（与 §6.1 口径相抵）。
- **B-4 块内 nib 计数与字节完成的关系**：1 槽 = 2 B = 4 nib，1 窗 = 16 槽 = 64 nib；nib 计数是**位置记账**（`slot = nib >> 2`，由槽号派生），不参与终止判定；"字节完成"才是终止判据（B-2）。两向反例：①nib 未满 64 而字节已取全（块末指令止于窗中，其后字节属下一项块）；②nib 达 64 而字节未取全（槽 15 起的 32 位指令还差次窗槽 0 的 2 B = 4 nib）。**I3-4**：任一时刻的"取指完成"与任何 nib/槽计数不互为充要。
- **I3-5**：`xw_carry` 是跨窗拼接的唯一载体（位宽与字段 = `spec/01` §3.16 ② 原文，62 bit = 1 + 16 + 40 + 1 + 4；载荷/消费/作废/粘滞违例规则逐句引用 §3.16 ②④，本篇不复述、不另赋值）。

4. **SC 权重更新**：按感知机式 `w[i] := w[i]+1`（实际 taken）／`w[i] := w[i]−1`（实际 not-taken），按输入位符号计；触发条件与动态阈值未在 `spec/00` §4 定值 ⇒ 不赋值，登记（§4 T3-2 行备注）。
5. **ITTAGE**：`cf`／`u` 的分配与递减同 1~2；`target` 在预测错误时按新解析目标改写。Alt／HBT 类增强＝三期项（【超】p.149-151 所列工程增强），一期不实现。

- `10` pop：`val := RAS[sp]`（该值即返回类分支的预测目标数据源，`P0` 快照读出）、入校正队列一条 `{ftq_id, 2'b10, val}`、`sp := sp−1`（`sp>0` 为前提）。
- `11` pop,then push：先 `10` 后 `01`（净效果＝TOS 替换；入队一条 `{ftq_id, 2'b11, val}`——`2'b11` 位携带「先弹」信息，供逆放）。
- 冲刷同拍（`flush_apply`）取消 `P2` 新项的一切 RAS 动作与入队（与 F4「冲刷优先」同拍口径）。
- RAS 仅预测性：任一构型下不影响架构正确性（`spec/02` §16.4-(2) 如实登记）。

**（d）上溢／下溢处置**

| 事件 | 条件 | 动作 | 可见性 |
|---|---|---|---|
| 上溢 | push 而 `sp==32` | **不压栈**（该 push 丢弃、`sp` 不动） | 置 `ras_ovf_sticky`（粘滞，只清于复位）＋饱和计数 |
| 下溢 | pop 而 `sp==0` | **不弹栈**（`sp` 不动、不入队）；该分支目标按回退次序取：①RAS TOS（不可用）⇒ ②BTB 条目 `target`（最近解析目标，§2.7）⇒ ③按不跳预测，待解析纠正（本篇推导） | 置 `ras_unf_sticky`（粘滞，只清于复位） |

- 粘滞位冲刷时**不清零**（(e) 的逆放按「实际发生的动作」执行，粘滞位使重放可复现）；环形覆盖／丢顶类替代策略不采用（破坏逆放可复现性）。

**（e）冲刷恢复（SARAS-lite；`spec/01` §5.2 `BP1..BP3` 行「RAS 用 SARAS-lite 恢复」）**

- 校正队列：深度＝`SARAS_FIX_QUEUE`=8；条目＝{`ftq_id` 5, `op` 2, `val` 40} = **47 bit**；总位量 8×47 = **376 b**；占用计数 `fq_occ`（4 bit，0..8）。全部位于预测器子系统内（非级间接口，不入 `spec/01` §3）。
- 恢复算法（冲刷生效拍、单拍完成；边界＝发起指令所属项 `boundary`；比较一律用 `older_5`（§1.2 F1），禁裸比较）：
  1. 自队尾（最新）向队首逐条检查：条目 `ftq_id` **严格比 boundary 年轻**（`older_5(boundary, e)` 为真且 `e≠boundary`）⇒ 逆放并弹出：`op=01` ⇒ `sp:=sp−1`；`op=10` ⇒ `sp:=sp+1` 且 `RAS[sp]:=val`；`op=11` ⇒ `RAS[sp]:=val`（先弹后压的逆＝恢复 TOS 值、`sp` 不变）。首个非年轻条目处停止（其及以下属 boundary 之前，保留）。
  2. 依据与健全性：逆放按时间倒序恰好抵消对应前进动作，故恢复后 `sp` 与 RAS 等于 boundary 处的投机态（构造性论证，本篇推导；原理句＝【超】p.140-144）。**条目集完备性**：保序提交 ⇒ 提交流未越过 boundary 之前其后的分支不可能提交 ⇒ 比 boundary 年轻的校正队列条目必全部在位（见 (f) 的回收纪律）。
  3. 与 checkpoint 路径交互：checkpoint 快照＝{RAT 整表, `SP_ck`, `FL_ck`} 三元（`spec/01` §5.3），**不含任何 RAS 字段** ⇒ RAS 恢复对 `needs_ckpt=1／0` 两条路径为**同一机制**、不依赖 `ckpt_id`；禁止为 RAS 另设快照载体（第二载体不做）。
  4. 时序：恢复单拍（校正队列深度上界 8 ⇒ 逆放 ≤8 条）；须在重定向后首个新项分配（首次 push／pop 读取）之前完成；与 `spec/01` §5.2 同行「清 GHR 投机历史、TAGE 不训练错误路径、IUM 取消待更新项」并列、互不依赖。
- 不变式 **I3-8（仅预测性）**：RAS／校正队列状态不出预测器子系统、不进任何架构可视结构；将其内容整体置任意值均不改变架构行为（断言面：复位／随机替换实验）。
- 不变式 **I3-9（校正完备）**：冲刷生效拍结束后，`sp`／RAS 等于 boundary 处状态；恢复完成前不得执行任何新 RAS 动作。

**（f）提交点校正（`bp_upd_t`；成员级定义见 §2.9）**

- 回收纪律：校正队列条目出队只允许发生在两处——①**提交出队**（本段）②**冲刷逆放**（(e)1）；其余任何路径不得移动或丢弃条目（这是 (e) 可复现的前提，也是 I3-9 的组成部分）。

- **身份键缺口（已闭合，Q-036/ISS-073，2026-09-24）**：上述判据所需的「条目 ↔ 已提交分支」身份键已由 `spec/01` v0.4 补全——`rob_entry_t`（§3.7）补 `ftq_id` 5bit，`commit_t`（§3.17）随提交携带 `ftq_id`；出队判据落定为：`commit_t.ftq_id` 匹配校正队列条目的 `ftq_id` 时出队。

## 3. 取指与 IBUF

### 3.1 消费侧：`valid` 且非 `err` ＋ `err_pos` 截断（`slot16_vld` 已删）

字段面（`spec/01` §3.16；ADR-3 / ISS-045）：`icache_rsp_t` 322 bit；`slot16_vld` 已删除（338 → 322，历史变更值）。半字可用性表达 = `valid` 且非 `err` ⇒ 全 16 槽可用；`err=1` ⇒ 按 `err_pos` 截断。消费者一览：

|---|---|---|---|
| C1 | `P5` walk（`vr1_ifetch` 内） | 起始位图 | 自块首槽起按 §3.16 ① walk；`err_pos` 命中槽处截断（其后槽不再产出起始）；其字节跨度含 `err_pos` 槽的指令必须带 err（含跨槽/跨窗情形） |

### 3.2 IBUF 满时的停工语义（F2 与 `P5`）

结构（引用）：IBUF 16 项 × 92 bit（`spec/01` §3.3）；`D` 每拍组合读出全部 16 槽并选取 ≤ `DECODE_WIDTH` = 4 个起始槽（`spec/01` §1.3）；槽清零粒度为 lane。

- **满判据**：无空 lane（16 lane 全部占用）⇒ 本拍不可写入。
- **停工（stop）语义**：`P5`（F2）本拍不写 IBUF、不推进 walk、不消费 FTQ 项；`xw_carry` 全字段保持稳定（§3.16 ④）；上游逐级反压——`P4` 不发新请求、`P3` 不出队（`rptr` 不前进）、FTQ 满则 `P2` 停写、BP 级停（§1.2 F3）。
- **正确性约束**：停工不置任何 err、不丢弃已 walk 结果、不改变任何已写入 lane；恢复 = `D` 消费释放 lane 后可当拍恢复（背压气泡上限与握手细化见 §5 下游义务）。
- **优先序**：冲刷优先于停工（F4 末句）；停工期间到达冲刷 ⇒ lane 按粒度作废、`xw_carry` 作废，恢复从重定向目标的新块重新开始。
