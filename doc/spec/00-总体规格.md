## 1. 目标与非目标

### 1.0 定位与路线决策（2026-09-22 由人确认）

**VR1 一期（本版）定位为"能力与方法证明"，不追 2026 年的性能主流应用级核。**

- 对标现实：今天"性能主流"（4~8 发射乱序 + RVV 1.0 + L3/多核一致性 + Sv39/48 + AIA + H，
  2.5~3.5 GHz）与"出货量主流"（RV32IMC 2~3 级嵌入式）是两个不同的目标，前者需数十至数百人年
  与先进工艺后端，不在本项目范围。
- **抬档窗口定在 M5 之后（实测 IPC 到手，预计约 12 个月）**，且必须是增量改动而非重写：
  ① D 提一期；② ALU→ALU 依赖间距 3 拍→2 拍（ISS-012）；③加 μop cache（须重定义
  `spec/01` §5.2 恢复点表）；④ L2 256KB→1MB 并预留 L3/一致性接口；⑤ RVV 仅留架构位不实现。
  每一项均触发 `doc/spec/00` 升版并重过 Requirement Review（红线 R5）。
- 该定位写进 `AGENTS.md` §1 项目信息，防后续讨论时目标漂移。

### 1.1 目标

| # | 目标 | 可判定出口 |
|---|---|---|
| G1 | 实现 RV64IMAC + Zicsr + Zifencei，特权 M/S/U + Sv39 + PMP 的**乱序超标量**单发射核 | riscv-tests rv64ui/um/ua 100% pass |
| G2 | 完全重命名 + 分组发射队列 + ROB 保序提交，乱序执行、按序提交、精确异常 | `doc/spec/05/06/09` 的 3 个手工推演例逐拍复现 |
| G3 | 解耦前端（FDIP）+ TAGE-SC-lite 分支预测 + RAS | 分支预测准确率 ≥ 94%（CoreMark 类负载，Verilator 实测） |
| G4 | 非阻塞 L1 + MSHR + store-to-load forwarding + 硬件 PTW | L1 miss 不冻结流水线（SVA：miss 期间仍可提交） |
| G5 | RTL 可综合、单时钟域、lint 0 warning | `verilator --lint-only` + RTL 评审 checklist（`spec/11`）通过 |
| G6 | 与自研 golden ISS 逐指令 trace 比对 0 mismatch | `doc/05` 回归记录全绿 |
| G7 | 架构上为 F/D 预留 PRF/ROB/旁路拓扑，二期不重构 | `spec/04`/`spec/06` 给出 FP 位宽与端口预留计算 |

### 1.2 非目标（明确不做，写出来是为了防止范围漂移）

多核与总线一致性协议（MESI 跨核）、Hypervisor（H 扩展）、Vector（V 扩展）、
Debug Module / JTAG / DTM、Trigger 模块（硬件断点）、Sv48/Sv57、AIA/IMSIC、
低功耗（DVFS/电源域/DFT/扫描链）、ECC、形式验证签核、FPGA 上板与物理实现、
循环终止缓冲 LTB 与双跳转（Two-Taken）预测。
**NMI 与 `Smrnmi`（2026-09-23 加入，源自 spec/01 评审 Q20）**：一期 `NMI_EN=0`，
不实现 NMI 也不实现 `Smrnmi`——不实现后者则 NMI “进得去出不来”；硬件致命错误上报走“置复位”。

**F/D 属"分期目标"**：一期不实现（FP 指令一律报 illegal-instruction），
但 CSR 的 `mstatus.FS`、ROB 的 `dest 类型`、PRF bank 划分必须按二期可展开的形式预留（见 §7）。

## 2. ISA 字符串与扩展分期

| 期 | ISA 字符串 | 说明 |
|---|---|---|
| 一期（本规格冻结范围） | `rv64imac_zicsr_zifencei` | 基线；特权 M/S/U + Sv39 + PMP8 |
| 一期附带 | `Zama16`（对齐原子性 16B）、`Zicntr`（cycle/time/instret 中的 CY/IR/TM 子集）、`Zifencei` | Zama16 由 §8 AMO/LR-SC 实现对齐保证 |
| 二期 | `+f+d`（→ `rv64gc...`） | 浮点流水、`mstatus.FS`、FRF 64×64b、FP 发射组 |
| 三期（研究项） | `+zba+zbb`、`+svinval`、RRIP 替换、数据预取、LTB/双跳转 | 每项独立评审，不进一期判据 |

**口径统一（重要）**：一期**不支持非对齐访存**——非对齐 load/store/取指一律报对应
address-misaligned fault。因此 golden ISS 与 Spike **一律不开 `--misaligned`**，
否则两侧口径不一致会把 ISS 差异误判成 DUT bug（登记 `doc/00` ISS-010）。

## 3. 微架构总览

```
                     ┌──────────────── 顺序前端（预测与取指解耦）────────────────┐
 预测流水 3 级:  bp_pc ─► [L1BTB/L2BTB + TAGE-SC-lite + ITTAGE-lite + RAS/SARAS] ─► FTQ(16)
 取指流水 3 级:  FTQ ─► [L1I 32KB/8w/64B VIPT + L1I TLB16 + PTW] ─► 对齐(32B) ─► IBUF(16)
                     └───────────────────────────────────────────────────────────┘
                                   │ 4 μop/拍
 译码/分发:  C 展开(1) ─► 定长译码(1) ─► 重命名(1)  ─► 分发(读PRF操作数) ─► 三路发射队列
                                   │ RAT32+PRF64          │
                                   │ checkpoint×4          ├─ IQ_INT 24 ─► ALU×3 / SHIFTER / MUL / DIV
                                   │ free-list             ├─ IQ_MEM 20 ─► AGU×2 ─► LSU(LQ48/SQ32/forward)
                                   ▼                       └─ IQ_BR  20 ─► BRU ─► 解析/冲刷
                              ROB 128（不存结果，按序提交 4/拍）─► retire trace ─► 与 ISS 逐指令比对
                                   ▲
                       唤醒/选择广播 wb_t{valid,paddr,data}（≤6/拍，CAM 相联比较）
```

- **顺序点**：只有 ROB 头条目能改架构状态；投机副作用（RAT 映射、PRF 数据、LQ/SQ 条目、
  cache 行 dirty、TLB 填入）全部设计成可撤销。这是精确异常的根，见【超】p.368。
- **两条反压链**：① `ROB 近满 / PRF 空 / LQ-SQ 满 / IBUF 空` → 反压分发；② `FTQ 满` →
  暂停预测流水。规则是**反压而非全局停**，避免整条流水线连锁停顿【超】p.397-401。

## 5. 关键机制的设计取舍备忘（评审时逐条过）

| # | 决策 | 选 | 否 | 一句话理由 |
|---|---|---|---|---|
| D1 | 重命名缓冲形态 | 融合式 PRF | ROB 存结果 | 【超】p.373-374：ROB 存结果条目宽度随数据宽增长，F/D 一上来就得重构；PRF 化提交零拷贝 |

| D3 | 发射队列形态 | 分组三队列 | 统一大队列 | 【超】p.211-213：CAM/仲裁代价随容量乘积增长 |
| D4 | 投机恢复 | checkpoint×4 + 回滚兜底 | 纯 checkpoint / 纯回滚 | 【超】p.200-201 中间态；4 份对应 R10000 档，耗尽时 8 条/拍回滚 |
| D5 | 前端 | FDIP 解耦 + FTQ | 顺序紧耦合取指 | 【超】p.157-160：I-cache miss 不冻结预测进度 |
| D6 | 分支预测器 | TAGE-SC-lite | 感知机主预测 | 【超】p.129-135：感知机加法器树占关键路径；且只能学线性可分 |

## 7. F/D 二期预留（一期必须做到的形式要求）

1. `PRF_FP_ENTRIES = 64`、`FRF_RD_PORTS = 8` 在 `vr1_pkg.sv` 定义但一期不例化存储阵列。
2. `uop_t` 内 `dst_kind[1:0]`（00 无目的 / 01 GPR / 10 FPR / 11 CSR-旧值）一期只用 00/01/11。
3. `rob_entry_t` 的 `fdirty` 位**一期用途 = 回滚归还判据**（该条目在 `S` 期分配过 PRF 目的号；`spec/01` §3.7 为该位语义权威）；二期 FP 置脏**另设新增位 `fp_dirty`**（一期不占位）。BLK-10/X1：原"一期恒 0"与 `spec/01` 定案相反，已按定案改写。
4. `IQ_BR_ENTRIES` 一期专供 BRU，二期与 FP 共组（条目须预留 `vs1/vs2` 编号域）。
5. `mstatus.FS` 一期读回 **恒 0（Off）**，非零写忽略；任何 FP 指令报 illegal-instruction。
   → 二期开启时只需改 `vr1_csr` 的 WARL 行为，不动 ROB/RAT/旁路拓扑。
