### 2.2 C 族格式与展开级

- C 族格式（实读佐证）：CI（行 12427、12580、12834）、CR（行 12378）、CB（行 12418、12623）、CIW（行 12540）、CJ（行 12344）、CA（行 12755）；其余（CSS/CL/CS 等）待补。
- **展开级**：C→32 bit 展开在 M04 `vr1_cexpand` 完成（`spec/00` §4.3 `C_EXPAND_STAGES=1`、§6 M04）；展开后为 32 bit 流进 IBUF 出口。
- **长度判定的唯一位置**：16/32 bit 判定只在 P5 walk（`spec/01` §3.16：槽半字低 2 bit ≠`11`→16 bit，下一起始＝当前+1；=`11`→32 bit，下一起始＝当前+2；起始可落任意槽号；槽 15 起始 32 bit 走 `xw_carry` 拼接，ADR-1）。**M04 不重判长度**，只消费 `fetch_raw_t.is_c`（`spec/01` §3.3）。
- `is_c` 生命周期（五级）：`fetch_raw_t.is_c`（§3.3）→ `uop_t.is_c`（§3.4）→ `rob.type[0]`（§3.6/§3.7）→ `excp_t.is_c`（§3.18）→ `rt_t.is_c`（§3.21）。

## 4. 首批逐指令条目（3 类，每类给格式样板）

### 4.1 类①：x0（硬连线零）相关

**前提**：x0 硬连线为全零（AN-01，行 1964）；`spec/00` §4.3 窗口可达性口径：融合式 PRF 之 31 项常驻架构态（x1~x31）⇒ 投机在途含目的 μop ≤ `64−31 = 33`。

| 条目（样板） | misa 扩展位 | μop 分解（数＋类型） | 目的/源操作数规则 | 异常条件 | 与 ISS 的对应点 |
|---|---|---|---|---|---|
| JAL/JALR 且 rd=x0（伪指令 `j`/`jr`） | I | 1 个；分支类（`type.bit1`） | rd=x0 ⇒ `dst_kind=00`：不分配 PRF 目的、不消耗 free-list、不进映射栈（`spec/01` §5.3 仅 `dst_kind≠00` 弹栈，A14）；源＝pc+imm 或 rs1+imm | 目标非规范地址 → instruction access fault（`spec/01` §3.12 `bad_va`；异常码表归 `spec/10`） | trace 无 rd 写；`rt_t.is_br=1` |
| 载入 rd=x0 | I | 1 个；访存类（`type.bit5`） | 结果丢弃（AN-01）；**访存照常发起**；"rd=x0 是否豁免异常/副作用"本片未取证，不预设（T-8） | 地址非对齐（`MISALIGNED_EN=0` 报 fault）、page/access fault | trace 记该 load 退休、无 rd 写 |
| ALU/移位/乘法 rd=x0 | I/M | 1 个；`dst_kind=00` | 同上；源依赖照常建立（分发读口照常参与） | 无（除零不异常） | 无 rd 写 |
| CSRRS/CSRRC 且 rs1=x0 | Zicsr | 1 个；`type.bit6`，`dst_kind=11` | **不写 CSR**（AN-07）：无写副作用、不因只读 CSR 报 illegal；rd≠x0 时读旧值写 rd | 读侧照常（AN-07：恒读） | `csr_old` 有值、`csr_new = old`（§3.21 合成） |
| CSRRW 且 rs1=x0 | Zicsr | 1 个；同上 | **写 0 到目标 CSR**（AN-08，与 CSRRS/CSRRC 相反）；rd=x0 时同时"不读"（AN-06） | 只读 CSR → illegal（AN-11） | `csr_new` 按 wdata=0 合成（可写位清 0、只读位不变） |

**不变式**
- **SI-1**：任何 `rd=x0` 的 μop ⇒ `dst_kind=00`；不分配 PRF 目的、不消耗 free-list、回滚不归还（`rd_is_new=0`）。依据：AN-01 ＋ `spec/01` §5.3/A14。
- **SI-2**：x0 作源的读值恒 0；31 项常驻架构态口径（x1~x31）与在途上界 33 引用 `spec/00` §4.3，本篇不赋值。
- **SI-3**：x0 目的不产生任何架构状态变化与 trace 写字段（`rt_t` 无 x0 写，§3.21）。

### 4.2 类②：RVC（Zca）展开

**前提**：长度判定唯一在 P5（§2.2/`SI-4`（纵①-F3 修正悬空编号）），M04 只展开不重判；展开后进 `uop_t` 的 `isop` 与 32 bit 形式相同（§3.6 C-2）。

| 条目（样板） | misa 扩展位 | μop 分解（数＋类型；展开形式） | 目的/源操作数规则（含保留点/HINT） | 异常条件 | 与 ISS 的对应点 |
|---|---|---|---|---|---|
| C.NOP | C | 1；展开 `addi x0,x0,0`（=NOP） | 不改任何用户可见状态（AN-21）；imm≠0 = HINT | 无 | `is_c=1`；pc 递增 2 |
| C.ADDI | C | 1；展开 `addi rd,rd,imm` | rd=x0 ⇒ C.NOP；rd=x0 且 imm≠0 = HINT；rd≠0 且 imm=0 = HINT（AN-17） | 无 | 同上 |
| C.LI | C | 1；展开 `addi rd,x0,imm` | rd=x0 = HINT（AN-16） | 无 | 同上 |
| C.LUI | C | 1；展开 `lui rd,imm` | 仅 rd≠x2 且 imm≠0 合法；imm=0 保留；rd=x2 且 imm≠0 ⇒ C.ADDI16SP；rd=x0 且 imm≠0 = HINT（AN-16、AN-23） | 保留编码点 → illegal（化归 T-9） | 同上 |
| C.ADDI16SP | C | 1；展开 `addi x2,x2,nzimm[9:4]` | 目的固定 x2；nzimm=0 保留（AN-17） | 保留点 → illegal（T-9） | 同上 |
| C.ADDI4SPN | C | 1；展开 `addi rd′,x2,nzuimm[9:2]` | 立即数零扩展、非零、按 4 缩放；nzuimm=0 保留（AN-18） | 保留点 → illegal（T-9） | 同上 |
| C.ADDIW（RV64 专有） | C | 1；展开 `addiw rd,rd,imm` | 仅 rd≠x0 有效；rd=x0 保留（AN-17、AN-23） | 保留点 → illegal（T-9） | 同上 |
| C.J | C | 1；展开 `jal x0,offset`（±2 KiB） | 无链接写（rd=x0，走 §4.1 规则） | 无 | `is_c=1`、`is_br=1`；pc 递增 2 |
| C.JAL（RV32 专有） | C | （RV64 不实现） | RV64 同位编码点 = C.ADDIW（AN-13、AN-23）；RV32 语义：link=pc+2 写 x1（AN-12） | — | 不出现（RV64） |
| C.JR / C.JALR | C | 1；展开 `jalr x0,0(rs1)` / `jalr x1,0(rs1)` | C.JR 仅 rs1≠x0（rs1=x0 保留）；C.JALR 的 rs1=x0 编码点 = C.EBREAK（AN-14、AN-22）；link=pc+2 | 保留点 → illegal（T-9） | `is_jalr_ret` 绑定待补（T-7） |
| 全零 16 bit（0x0000） | C | — | 规范永久保留为非法指令（AN-20；全 1 同理） | illegal（T-9） | trace 侧须有异常条目 |

**不变式**
- **SI-4**：16/32 bit 判定**唯一**在 P5 walk（`spec/01` §3.16）；M04 展开级不得重判（否则双判定点会产生"同一字节流两种切分"的假绿）。
- **SI-5**：C 展开为 **1:1**（一个 C 指令产出一个 μop）——`UOP_MAX_SPLIT=2` 仅 DIV 与 AMO（`spec/00` §4.3）；C 类不拆包。
- **SI-6**：`is_c` 五级链（§2.2）逐级传递，任何一级丢失都会使 trace/ISS 的 pc 递增与异常现场口径分叉。
- **SI-7**：C.JALR 的 link 值（pc+2，AN-15）与 base 指令 JALR（pc+4）不同——RTL 与 ISS 两侧必须同口径，落实方式见 T-10（本片不定实现）。

### 4.3 类③：CSR（Zicsr）

**前提**：6 条 CSR 指令（AN-03）；读写条件三要素（rd、rs1、指令）见规范 Table 21（AN-10）；uimm 为 5 bit 无符号、零扩展（AN-09）。

### 9.2 计数与未决结构面（编码面的前置裁定项）

计数分解：`19＋9＋10＋11＋11＋13＋6＋8 = 87`（对应 C-4 的 1024−87＝937 余量）。列序说明：`ADDI` 等 19 项含 OP-IMM 9；OP-32 共 9（非 10）；RV64I 基础（不含 CSR/特权）为 53 项，含 CSR 6 与特权 4 及 SYSTEM 全组为 63 项（§10 计数按 63）。

未决结构面（下列七项未裁定前，任何下游不得按臆测实现——同 §3.6 撤销点口径）：
- (1) 立即数型与寄存器型是否共码（区分为 `imm_kind`＋`src_sel`（§3.8））——影响 §9.1.1／9.1.2／9.1.4。
- (2) 条件分支 6 条聚合为 1 码（条件内嵌 `isop` 域）或分列——两案对 `disp_x_t`（§3.11）无位宽影响。
- (3) 载入/存储是否按 `dm`（§3.8／§3.11）＋`sext` 聚合。 
- (4) CSR 6 条聚合形态（由 `csr_wr_type`（§3.11）与 `op`（§3.19）区分）——前置＝T-2。
- (5) NOP（C.NOP 展开目标）是否独立成员，及其与 `is_c`（§3.3）标记的配合。
- (6) `cls[2:0]`（§3.8）与本表成员的映射关系（登记缺口见 §12 的 T-19）。
- (7) `FENCE` 的 fm/pred/succ 承载域（复用 `imm` 44 bit 之一部或编码常量）——与 `spec/01` §3.8/§3.11 的 `imm` 语义边界相关。

**保留段**：未被 §9.1 占用的 `1024 - 87 = 937` 个组合全部 **reserved**。两条硬规则：①各占位内超出已用成员号的编码（如 000.g0 的 m=9..15、111.g1 的 m=11..15）与全部未列出的 (cls.g) 组号一律 reserved；②**reserved 组合不得由译码产生**——`vr1_decode` 不得对其断言任一合法语义，非法化路径与异常码归 `spec/10`（T-9 出口）。

**依据句（保留≠非法；L12 补，`doc/verify/05` R-099；附 Z 澄-4）**：规范口径＝保留编码的译码行为 **UNSPECIFIED**（行 2026–2029：「The behavior upon decoding a reserved instruction is UNSPECIFIED.」「Some platforms may require that opcodes reserved for standard use raise an illegal-instruction exception. Other platforms may permit reserved opcode space be used for non-conforming extensions.」——后句跨页拼接：行 2029 末「non-」与行 2034「conforming extensions.」之间隔页脚与页标记）；故「保留」**不自动等于「非法」**，平台可选非法化（行 2028–2029）。**本项目取「RES 编码点一律非法化」为平台选择**（行 2028–2029 允许；D-1 修复与对应断言即按此选择，`doc/verify/05` R-097），非法化路径与异常码归 `spec/10`（T-9；`spec/10` 落文时须引本依据句并定 RES 异常码——L12 登记，只登记不越篇）。明文例外按规范原义执行：FENCE 保留配置**按 FENCE 处理**（行 3120–3124：「Base implementations shall treat all such reserved configurations as FENCE instructions (with fm=0000)」）；全 0／全 1 16 bit 指令**规范明文非法**（行 12798–12804：「A 16-bit instruction with all bits zero is permanently reserved as an illegal instruction.」，全 1 同理）；保留空间中的 HINT 段不改变架构状态、照常执行（行 3207 起：「HINTs do not change any architecturally visible state, except for advancing the pc and any applicable performance counters.」）；SLLI-W 族 `imm[5]≠0` 标注 reserved（行 3516–3522，变更注：「Previously, SLLIW, SRLIW, and SRAIW with imm[5]≠0 were defined to cause illegal-instruction exceptions, whereas now they are marked as reserved.」）——本项目按平台选择仍非法化。

### 16.4 T-4／T-7／T-10／T-11 补写（本篇内可闭合项）

**(1) T-4——`is_comp` 语义细化（裁定：一期恒 0）**

- 产生规则：**一期 `is_comp` 恒 0**（`type.bit2` 不置位）。理由：`spec/01` §3.6 字面「C 展开的第二半」被 SI-5 排除——C 展开 1:1（一个 C 指令产出恰一个 μop），`UOP_MAX_SPLIT=2` 仅 DIV／AMO（`spec/00` §4.3），二者均无「第二半」构型；C-5（C 展开零新增成员）同口径。
- 与 `UOP_MAX_SPLIT` 的关系：**无**。DIV 商／余、AMO ld+op+st 的拆包是同一 base 指令的 μop 序列，其第二 μop 不借用 `is_comp` 语义。
- 撤销／回退点：二期若引入「C 拆半展开」（一个 C 指令产出 2 μop）则升版恢复语义；**在此之前任何下游（断言／覆盖率／ISS）不得依赖 `is_comp=1`**。
- 边界：`spec/01` §3.6 字面为本位定义的描述（条件不可达），**不冲突**；如需字面同步（改为「保留位，恒 0」）由 `spec/01` 后续片承接（登记）。
- 状态：**关闭（本篇口径）**。

**(2) T-7——`is_jalr_ret` 产生规则（裁定：定案）**

- 规则（L12 更正，`doc/verify/05` R-099；附 Z 阻塞-1）：**`is_jalr_ret = 1 ⇔ (isop=JALR) ∧ (rs1 ∈ {x1, x5}) ∧ (rd ≠ rs1)`**（弹栈面精确谓词）；其余情形（含非 JALR）恒 0。推导：Table 2 第二行「Pop」＋第四行「Pop, then push」⇒ 弹栈 ⇔ `rs1∈{x1,x5} ∧ ¬(rd∈{x1,x5} ∧ rd=rs1)`；因 `rd=rs1 ∧ rs1∈{x1,x5} ⇒ rd∈{x1,x5}`（该合取与 `rd=rs1` 在 `rs1∈{x1,x5}` 下等价），故化简为 `rd≠rs1`；第五行「Push」（`rd=rs1∈{x1,x5}`）排除该边缘。
- 依据（行级锚，本片取；L12 更正行号范围，`doc/verify/05` R-099；附 Z 阻塞-1）：行 2722–2757（Table 2 跨页：主体 2727–2746／页脚 2747–2748／页标记 2750／续页第五行块 2751–2757）——「A JAL instruction should push the return address onto a return-address stack (RAS) only when rd is x1 or x5. JALR instructions should push/pop a RAS as shown in Table 2.」（行 2724–2726）＋ Table 2 全表五行（行 2727–2746 含表头与前四行；行 2751–2757 含续页表头与第五行）：`rs1∈{x1,x5}` 的**两行**动作含 Pop（行 2735–2738「Pop」＝rd∉{x1,x5}；行 2743–2746「Pop, then push」＝rd∈{x1,x5} 且 rd≠rs1）；第五行 `rd=rs1∈{x1,x5}`＝「Push」（行 2751–2757）。
- 设计口径：本位只承载**弹栈面**（RAS 预测用「该 JALR 将弹栈」）；push 面不需专用位——`rd∈{x1,x5}` 由 μop 的 rd 字段直接判（行 2724–2725 对 JAL 的同一规则）。
- 边界（L12 更正，`doc/verify/05` R-099；附 Z 阻塞-1）：RAS 的实际更新／替换／预测用法归 `spec/03`（不越篇）；**Table 2 已列** `rd=rs1∈{x1,x5}`（如 `jalr x1,0(x1)`）一格——规范动作＝**Push（仅压不弹）**（行 2751–2757「Yes／Yes／Yes→Push」；正文印证「If rs1 and rd are the same link register (either x1 or x5), the RAS is only pushed…」，行 2762–2765）；由此该边缘**不弹栈**（本位按新谓词取 0）；RAS 仅预测性、不影响架构正确性（如实登记）。
- ISS 侧：无 RAS 对应物（不进 trace 比对，`iss/README` §3）⇒ 无互校项。
- 跨篇联动登记（L12；只登记，不改他篇）：`spec/03` T3-5（RAS/SARAS 推入／弹出细则；其表内已声明与本篇 T-7 合并定稿）与 `spec/01` §3.12 `is_jalr_ret` 标签（现文「RAS 更新用」）须同步按新谓词承接（`doc/verify/05` R-099）。

**(3) T-10——C.JALR link 值的两侧落实口径（裁定：定案）**
