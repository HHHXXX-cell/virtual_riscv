## 1. 流水级定义

**片①-A9 定义（D-14 决策片，2026-09-23，见 `doc/verify/05` R-049）**：**后读**工程内定义 ＝ **出队（选择）拍读 PRF**；源值唯一载体 ＝ §3.11 `disp_x_t`（`rs1_val/rs2_val` 128 bit）。`P8`/`S` 只做就绪初值判定、**不读源值**。

**纵①-F5 改注（D-14 决策片，2026-09-23，见 `doc/verify/05` R-049）**：本表 `P9` 行的**翻选触发判据**代号＝**`PT1`/`PT2`**（旧名 `T1`/`T2`）；同型撞名三族另两族＝批中止判据（`AGENTS.md` 规则 10，改 `AB1`/`AB5`/`AB6`）与 `spec/02` 的 `T-1..T-19`（维持原名），三族自此分域。

**关键时序结论（须在 `spec/13`（该篇待建） 性能模型里体现）**：`WB(P15)` 与唤醒同拍，选择/发射在下一拍 `P9'`，
执行再下一拍 → **ALU→ALU 最短依赖间距 = 3 拍**（非旁路最优的 1 拍）。这是"后读 + 唤醒/选择分离"
换来的代价，依据与折中见【超】p.216-223、p.221-223；缓解手段是乱序窗口（ROB 128、6 发射）
覆盖依赖距离，而非把旁路网络加宽。**若 `spec/13` 的模型显示 IPC 因此达不到 1.8，回炉选项记录在
`doc/process/00`（新增条目），可选：①缩短到 2 拍（唤醒同拍完成选择，时序风险）；②前读 + 加宽 PRF 读口。**

### 1.2 为什么 IBUF 在译码之前（F2 写、D 读）

参照 P6 的解耦前端顺序：取指 → 指令队列 → 译码（ISB 引导）→ 重命名【超】p.415-419。
好处：①`F1` 的 L1I RAM 读与 `P0-P2` 的预测在时间上解耦，miss 时预测器可继续领先跑（FDIP）
【超】p.157-160；②译码器只消费已对齐、已落队列的指令字，缺失不再污染译码级；
③IBUF 只需存原始指令字（省面积），不必存 200 bit 的已译码 μop。
代价：`D` 级一拍内完成 C 展开 + 译码 + 立即数生成 + 非法预检，是关键路径候选（`spec/02`（该篇待建） 里
按"展开查表 + 译码并行"处理：RV64C 展开为纯组合 64 项映射表）。

### 1.3 每拍吞吐

| 级 | 每拍最大数 | 参数 |
|---|---|---|
| 预测 | 1 个 FTQ 项（1 个预测块） | — |
| 取指→IBUF | 32 B / 16 个 16bit 候选槽（8 个 32bit 槽） | `FETCH_BYTES` |
| 译码 | 4 条（C 展开后统一 32bit 形式） | `DECODE_WIDTH` |
| 分发 | 4 μop | `DECODE_WIDTH` |
| 发射 | 6 μop（分 3 组：INT≤4、MEM≤2、BR≤1） | `ISSUE_WIDTH` |
| 写回 | 6 结果 | `WAKE_BCAST_PORTS` |
| 提交 | 4 条 | `COMMIT_WIDTH` |
| trace | 4 条 | `COMMIT_WIDTH` |

> 分组上限（INT≤4 / MEM≤2 / BR≤1）是各组的读口与执行单元数上限，不是队列条目数；
> 三组之和 7 > `ISSUE_WIDTH=6`，由选择器按年龄仲裁，见 `spec/05`（该篇待建）。

## 3. 级间接口（struct 位域）

### 3.1 `ftq_req_t` — `BP3 → FTQ`（写，1/拍）

| 成员 | 位宽 | 语义 | 合法值域 |
|---|---|---|---|
| `valid` | 1 | 本拍有块入队 | |
| `pc` | 40 | 块起始 VA | 2 字节对齐（`pc[0]==0`；N-03：RVC 下条件分支/JALR 目标可 2 字节对齐，重定向后下一块起始=该目标，原"4 字节对齐"不可满足） |
| `nib` | 5 | 块内指令条数 | 1..16（0 保留；N7：32B 窗口全 RVC 可达 16 条，原 3 bit 三处口径互斥——编码容不下值域上界 8、又盖不住 16 槽，位宽按值域上限定） |
| `br_vld` | 1 | 块尾是分支 | |
| `br_type` | 2 | 00 条件 / 01 无条件 JAL / 10 间接(JALR) / 11 调用-返回对 | |
| `taken` | 1 | 预测方向 | |
| `target` | 40 | 预测目标 VA（`taken=1` 时有效） | 2 字节对齐 |
| `ras_op` | 2 | 00 无 / 01 push / 10 pop / 11 push+pop（尾调用） | |
| `ras_top` | 40 | push 数据 = `pc + 块内该分支长度` | |
| `pred_conf` | 2 | 置信度 0..3（SC 输出幅度分级） | |
| `bp_upd_id` | 8 | 预测更新表索引（提交反馈用；表结构与深度归 `spec/03`——**该篇待建**，N15③/CLR-02） | 0..255 |
| `bad_va` | 1 | `target` 非规范地址 | |

合计 1+40+5+1+2+1+40+2+40+2+8+1 = **143 bit**（机器核对通过；N7：`nib` 加宽后由 141 同步至此）

**FTQ 项覆盖范围（Q39 定死）**：一个 FTQ 项只覆盖到块内**首个可预测分支**为止（截断规则）；块内其后可能存在的分支由下拍重新走 `P0..P2` 预测。多分支块与双跳转列三期（`spec/00` 非目标）。`br_vld=0` 的块不消耗 checkpoint、不写预测表。

### 3.2 `ftq_entry_t` — `FTQ → IF`（读，≤1/拍）

= `ftq_req_t` 全字段（143 bit）+ 下表 2 个成员：

| 成员 | 位宽 | 语义 |
|---|---|---|
| `= ftq_req_t`（全字段复用） | 143 | 见 §3.1，机器核对基准行 |
| `icache_ready` | 1 | 缺失时为 0，令该项**停留队头**而非丢弃 |
| `ptw_req` | 1 | 该块需 PTW 预取 |

合计 143+1+1 = **145 bit**（Q34 引用的 `ptw_spec_id` 已改为本篇实际存在的 `ftq_id`；N14：原 `seq_of_ftq` 字段删除——读出口的序号由 FTQ 读指针自带，该字段既冗余又与 `ftqid_t` 构成双编码）

### 3.3 `fetch_raw_t` — `IBUF → D`（每拍至多 16 个候选槽，`D` 级消费 ≤4 条）

| 成员 | 位宽 | 语义 |
|---|---|---|
| `valid` | 1 | 该 lane 有指令 |
| `pc` | 40 | 该指令首地址 |

**csrq 的五条硬规则（第 6 轮 BLK-01/02/03 补齐；第 10 轮 H-05 补第 4 条；第 5 条＝异常提交的 CSR 写抑制（D3-①，2026-09-24，见 `doc/verify/05` R-076）；计数更正：原“四条”漏计第 5 条，2026-09-24，见 `doc/verify/05` R-090）**：

1. **冲刷作废**：入队顺序 = 程序顺序，故冲刷时直接把队列**截断到冲刷点之前**——保留**比冲刷分支更老**的条目，判据 `older(e, f) ≜ ((f − e) mod 256) < 128`（`e`=条目 `rob_id`，`f`=冲刷分支 `rob_id`；与 `robptr_t`/`seq_t` 同回绕减法口径，**禁裸比较**——N-07：裸 `≤` 在 `rob_id` 回绕后判定反向，BLK-01 原后果复发）；否则僵尸条目会卡住队头，且 `rob_id` 回绕后会误命中陈旧 `addr/op/wdata`。**D3-① 注（2026-09-24，见 `doc/verify/05` R-076）**：`older(e, f)` 为**非严格**关系（`e==f` 判真）；串行化类冲刷点 B 正常退休、其队头条目由提交拍命中 `csr_wr` 正常消费；**trap 类 B 随异常提交“丢弃出队、不产生 `csr_wr`”**（本小节规则 5）——原“队头僵尸”构型（附 N 存-1）就此闭合。
2. **`src_val` 的解析责任在 `R` 级**：`src_val` = 该指令 rs1 语义值，来源由 `imm_kind`/指令类型判定（寄存器型取 `rs1_val`，**I 型 CSR 取 `imm[4:0]` 零扩展**——CSR uimm 是 5 bit **无符号**数【用】§2.8；N13：原"符号扩展后的 imm"会在 uimm≥16 时与 Spike 分叉，分叉点落在 `csr_wr.wdata`，属假红或静默写错）——故 `csrq_entry_t` 不需另带 `imm` 字段。
3. **同包多 CSR = 序列化提交**：一个提交包内一旦出现 `type[6]=1`，本拍**只提交最老的那条**，同包其余 lane 下拍重提（否则除最老 lane 外的 CSR 全被静默跳过，A12 也检不出）。
4. **两个写口的"命中失败"语义（H-05）**：`W` 级写 `src_val`（后读拍）、`E` 级写 `old_val` 两写口（**BLK-3 更正（2026-09-24，A7 复核，见 `doc/verify/05` R-086）**：原“`S` 级写 `src_val`”及本节构造性上界式中的 `S` 写均为 A9 落文前旧名——后读＝`W` 发射选择拍、`S` 不读源值，已统一改 `W`；I 型 `src_val` 在 `R` 级入队即写定，见规则 2 与 `csrq_entry_t` 行），均**只在 `rob_id` 命中且该条目仍有效时写入**；未命中（含条目已被规则 1 冲刷截断、或写入到达时该项已提交出队）一律**静默丢弃**，不得改写任何其他条目——若实现成"无条件写固定槽"，迟到写回会污染邻条目；反之，本队列能容忍迟到写回，正是靠"入队序=程序序 + 截断作废 + 写口按 `rob_id` 命中"这三条合力。**I-02 定案（ISS-041 选 A′，2026-09-23 决策 AI ADR-2，取代原 C 推迟）**：①**构造性上界**——`W` 写 < `E` 写 ≤ `E` 拍；`finish` 在 WB 置位、当拍方可见，出队只在 CT 且以 `finish` 为提交资格 ⇒ **出队拍 ≥ finish+1 ≥ 写口点火+1**（1 拍执行体：`E`=t、WB=t+1、CT≥t+2、写 ≤t，余量 ≥2 拍；更长的 EU 只拉大差距）⇒ **非冲刷条目的合法写恒先于出队**，"写入到达时该项已出队"只可能属被冲刷截断条目（该 μop 不提交、不产 trace、`rd_data` 无消费方）⇒ 丢弃无损；②**丢弃两分类可见化**——未命中写点火拍 = `t`，若 ∃ 截断生效于 `[t−K, t]`（含同拍，**截断优先**）且写 `rob_id` 在截断侧（`!older(e,f)`，与规则 1 同口径、**禁裸比较**）⇒ 计 **`drop_cnt_squash`**（合法）；否则置 **`sticky_drop_illegal`**（只清于复位）；**`K`＝2（写口在途界）——已由 `spec/04` 定值**（`K ≥ max(L_S, L_E)` 逐级算式＋紧致性＋回退点见该篇；机制不动、值来源改判；`doc/verify/05` R-048；本条与 §7 A17 窗口 2026-09-24 回写、A7 复核 CLR-2 见 R-086；原“暂定 2、定值归属 `spec/04`、定值后回写”等句作废；`L_x`＝写口 x“条目可截断点→写点火”最坏在途拍数，含队满反压/停顿——记法沿用该篇）；**`spec/13` 仅引用 `K` 建模、不改值**，`spec/11` 仅消费（A17 窗口参数）。**默认值期间三条锁定（附K-B3b-2）**：(a) 两分类计数与 `sticky_drop_illegal` 必须实存可观测；(b) **"A17 未报错"不得当通过证据**（窗口暂定，相关 PASS 须标注）；(c) 不得据此豁免"闭合前丢弃必须可见"的约束。**若 `K*≠2`**：只动数值引用点、不动机制（§3.19 数值→K*；§7 A17 `$past` 窗口 1..2→1..K*；§10 ISS-041 行回填）；`K*&gt;2` ⇒ 此前"无 sticky"结论须重跑（潜在假绿）；`K*&lt;2` ⇒ 历史假红清账；A18 不涉窗口不动。**该计数的消费方（附K-A1-C5 补）**：**不占 PERF 事件表**（`PERF_EVT_NUM=8` 已定死，见 §3.22 与 `spec/00` §9——如需 perf 出口须起升版讨论，不得私下占位），其消费面＝① `doc/verify/02` 验证点（"冲刷性丢弃被实际命中"须有覆盖项）② `spec/13` 引其定义域做时序论证；③§7 新增 **A17/A18**（+A19 可选）把两类丢弃变硬红——**不得把"丢弃"作为合法写路径的兜底** |

5. **异常提交的 CSR 写抑制（D3-①，2026-09-24，见 `doc/verify/05` R-076）**：`exc_v=1` 的提交条目命中 `csrq` 队头时**不得产生 `csr_wr`**；该队头条目随本次提交**丢弃出队**（不写映射、不产生写脉冲）——异常提交只执行 trap 入口动作，被终止条目的 CSR 写不得落地；命中判定在后续条目上**重新起算**（后续 CSR 按新队头重新匹配，不因本次丢弃漏判）。

**冲刷总延迟（Q16 定死两档）**：

  `R` 恢复 1、`F0` 重发 1、`F1` L1I 读 1、`D` 出 1）。**N2 定案后本档无弹栈代价**——栈指针重置 `SP:=SP_ck` 为 1 拍组合动作，不延长 `rollback_busy`。
- **无 checkpoint（逐条回滚）**：**5 + ceil(待撤销映射数 / `ROLLBACK_RATE`)** 拍；`ROLLBACK_RATE=8`。**待撤销数上限取参数 `ROLLBACK_MAX`（**已于 2026-09-23 定值＝33**（ADR-S2），`spec/04` 只做复核与联动公式）——不得写死 128**（附B-B7）；**两口径裁定（附M-B-5，2026-09-23）**：`ROLLBACK_MAX=33`＝**运行紧界**（回滚弹出数 ≤ 栈深 `HIST_DEPTH=33`），**延迟公式与活性界一律取它**；`ROB_ENTRIES`＝**不含栈深约束的粗上界**（历史推导件，仅作 `spec/04` 容量论证的保守对照）；栈只存已过 `R` 级的写 RAT μop，`R` 级在途组由 `!flush_apply` 门控保证冲刷当拍零副作用（B-3 定案）、无需恢复——原"+`R` 级在途组"不再需要）。原稿宣称"冲刷 5 拍完成"对无 checkpoint 分支不成立。**活性界同源（D3-⑤，2026-09-24，见 `doc/verify/05` R-076）：回滚全程完成 ≤ `5 + ceil(ROLLBACK_MAX / ROLLBACK_RATE)` ⇒ ≤10 拍，见 §5.3 末。常态登记（附M-D4-④）：B-8① 后本档由稀有转常态——回滚档 `5+ceil(n/8)`（最坏 10 拍）频度画像与停顿影响转 `spec/13`（台账号 ISS-060）。**
- 回滚全程 `rollback_busy=1`，**门控范围定死为“只挡新指令进入 `R`/`S`（`P6`/`P7` 入流使能）”**；**回滚执行体（栈读、RAT 写、free-list 归还、尾指针与队列清理）不受门控**，且回滚不申请任何分配资源 ⇒ 与 BP1~BP6（均为资源状态反压）**无反压互等，排除条件性死锁**（B9：原句未写门控范围，读作“`R` 级整级冻结”时与回滚推进互等）。否则新指令会写进半回滚状态的 RAT，映射被交错改错。
**若启用 μop cache（三期预留）**，误预测需额外清/失效对应行，恢复点表须重定义——
此预留改动在 `spec/03` §预留 中记录（**该篇待建**，附B-C7），一期不做。

### 5.3 冲刷与反压的交互

**映射历史栈（Q17 定死方案；第 8 轮处置 N1/N2/N3 重构，BLK-05/06 随之定案）**：逐条回滚只读该栈，
**不依赖 ROB 条目**——否则“冲刷当拍就清 ROB 尾指针并释放投机项”会让回滚无数据可用。ROB 释放与回滚就此解耦，
同时解开与 `rob_near_full` 同拍重算的矛盾。

**栈条目（单一融合形态，N3 定案；N-01 补元）**：`{arch[4:0], old_paddr[5:0], new_paddr[5:0], new_alloc, br_mark, rob_id[7:0]}` = **27 bit**（`new_paddr`+`new_alloc` 供逐条回滚显式归还物理号；checkpoint 路径经 `FL_ck` 批量回池，两路径互补；**附M-B-1 定案：栈条目 27 bit 不变、struct 位宽零变更**）。
**每个写过 RAT 的 μop 恰好压入一条**（**附M-B-2 定案：冲杀 lane 同样逐条压入**——被杀 lane 并入压栈，见下）：普通 μop `br_mark=0`；分支 μop `br_mark=1`——**分支自身映射与分支标注融合为一条**（**附M-B-1 定案：`br_mark` 降级为调试/断言用标注、不再作终止键**）（原“映射条目 + 独立 br_mark”两形态下，“弹到标记即停”会残留分支自身映射未撤销，且 R/S 两级双写口的压栈顺序无解，N3）。

**压栈点唯一 = `S` 级（`P8`）**：`rob_id` 在此已分配；按 lane 序（0→3）压入，每拍 ≤4 条、单写口。
**冲杀 lane 并入压栈（附M-B-2 定案，2026-09-23，见 `doc/verify/05` R-067）**：撤销原“本拍被冲刷作废的 lane 不得压栈”子句——冲刷当拍被杀 lane 的压栈载荷与常态压栈**同源复用**（`S` 级组合可得，零新增存储/端口），入栈序＝lane 序、≤4 条/拍；被杀条目严格比 B 年轻（**不含 B 自身**）、**无需 `older()` 判定**；checkpoint 路径 `SP := SP_ck` **取覆盖**（不弹、由 `FL_ck` 托管，防双归还；**当拍唯一有效 `SP` 写者**——与冲杀压栈同拍＝覆盖胜出、压栈撤效，被杀条目不得落入 `SP_ck` 之下，D3-②）；rollback 路径由 §5.3 终止规则（D3-① 三边界判定）自动弹出；否决第二载体（+144 bit 与跨档仲裁）与排空（冲刷延迟 5→6 拍全情形）。
**`R` 级在途组不入栈（附M-B-3 定案收窄）**：`R` 级变更（`r_alloc_grant`/RAT 写）以 **`!flush_apply` 门控为唯一防泄漏机制**——冲刷当拍 `R` 级零副作用、**泄漏界＝0**；原“在途映射寄存器（每 lane `{arch, old_paddr}`）当拍直接恢复”**删除**（门控后无读取窗口；**等价变体回退注**：若保留须同时携带 `new_paddr`+`new_alloc` 与归还口，否则物理号泄漏——`doc/verify/05` R-067 ADR-B3）。
两级压栈/双写口/同拍顺序问题就此消除（BLK-05“rob_id 时点无值”与 N3 的定案）。

**提交弹栈（N1 定案——原设计只有回滚一个弹者，直线代码下栈单调填满反压成永久停摆）**：
`CT` 每提交一条写过 RAT 的 μop（`dst_kind≠00`）即从**栈底**弹出其对应条目（只丢弃、不写 RAT）。
栈序 = 程序序 = 提交序，故栈底条目的 `rob_id` 必等于最老未提交的写 RAT μop；不匹配或空栈属实现缺陷，由 §7 **A14** 兜底置致命。
提交弹栈动**栈底指针**、回滚/清栈动**栈顶指针**，两者相向而动互不重叠，相遇即空栈。

**逐条回滚（flush at B，`needs_ckpt=0`）终止规则（附M-B-1 定案，2026-09-23，见 `doc/verify/05` R-067）**：**起弹拍＝`flush_apply` 生效次拍**（当拍仅完成压栈与门控；当拍压入条目对次拍起弹出可见；RAT 改写次序＝**由新到老**——D3-②）；以 `ROLLBACK_RATE=8` 条/拍从栈顶弹出：每弹一条即将
`RAT[arch] := old_paddr`，且条目 `new_alloc=1` 时将 `new_paddr` 归还 free-list；**终止谓词写死三边界（D3-① 定案，2026-09-24，见 `doc/verify/05` R-076）**：令 `d ≜ (B − e_top) mod 256`——`d==0`（栈顶即 B）⇒ **停弹（B 保留）**；`d∈[1,127]`（栈顶严格老于 B）⇒ 停；`d==128` ⇒ **致命不弹**（序违例防御、构造不可达）；`d∈[129,255]`（栈顶严格比 B 年轻）⇒ 弹（`older(e, f) ≜ ((f − e) mod 256) < 128` 口径、**禁裸比较**；**“等价书写”单式暂缓落文**：R-076 所给之式与本节三边界相抵，纠正前一律以三边界枚举为准，见 `doc/verify/05` R-078 未完成列）；原“非严格老于 B（B 自身或比 B 年轻）即弹出（B 自身映射必被撤销）”表述**作废（D3-①）**——被杀集合＝**严格比 B 年轻**，B 自身保留在场、不弹栈；**空栈＝正常完成**（被冲刷路径条目全数弹出，无残留）；**致命路径收窄为“序违例”**：`(B − e) mod 256 == 128` **不可达**（`older()` 在该值上语义歧义、构造上不可能命中），出现即置致命错误并复位（防御路径）。原“弹出 `br_mark=1 && rob_id == B` 的融合条目才停”**作废**（非分支 B 无同型载体、原规则对其不终止）；`br_mark` 保留但降级——不再作终止键，仅留调试/断言用标注。备选方案（回退点，ADR-B1）：显式深度计数器（记录 B 对应栈深），仅在**三值边界判定**被证伪时启用（D3-①）。**（建议，编号待 `spec/11` 定稿）**：回滚全程完成 ≤ `5 + ceil(ROLLBACK_MAX / ROLLBACK_RATE)`（参数引 `spec/00` §4.3；取 `ROLLBACK_MAX=33`、`ROLLBACK_RATE=8` ⇒ **≤10 拍**——D3-⑤，2026-09-24，见 `doc/verify/05` R-076；**原“≤6 拍”撤销**，原值无推导来源）。进展口径：首个弹出不迟于 `flush_apply` 生效次拍发起。

**checkpoint 恢复（flush at B，`needs_ckpt=1`）的栈与 free-list 处置（N2/N-01 定案）**：checkpoint = **三元快照** `{RAT 整表, 栈深 SP_ck, free-list 分配指针 FL_ck}`。恢复动作（1 拍）：①`RAT :=` 快照整表；②`SP := SP_ck[B.ckpt_id]`——**B 之上**（B 自身保留、由提交弹栈配对）的栈条目就地作废，由后续压栈自然覆盖（后续逐条回滚不会再弹出陈旧条目）；③`free_list.head := FL_ck[B.ckpt_id]`——**严格在 B 之后的一切分配自动回池**（分配序 = 程序序，`(FL_ck, 当前 head)` 区间的物理号只可能被 B 之后的 μop 取走），被作废栈条目因此**无需逐条归还**，堵住 checkpoint 路径的 PRF 号泄漏（N-01：原二元快照下这些号既不在 RAT 新映射也不在 free-list，单调泄漏至 `free_list_empty` 死锁）。提交回收推的是尾指针，与 head 重置天然衔接（free-list 环容量条件归 `spec/04`）。`SP_ck` 采样点 = `S` 级 lane 序处理到 B 时、B **压栈后一刻**（D3-① 改：快照含 B 的效果，与 §5.3 快照时点段“B 生效后”一致）；同组比 B 老的 lane 条目在 `SP_ck` 之下、保留不动。

**重定向与重取（D3-①，2026-09-24，见 `doc/verify/05` R-076）**：flush at B 后的取指去向按 B 类别分三路，**B 自身一律不重取、不弹栈（不因自身落入回滚谓词）**：①**分支类 B**（条件/JAL/JALR 误预测）——重定向取指到 `target_real`（§3.12），B 继续在途直至正常退休（映射保留，承载 JAL/JALR 的 `rd` 链接值）；②**串行化类 B**（写 `mstatus`、MRET/SRET，§3.18 Q29）——**提交时冲刷**在途指令，返回目标与 `mode` 由 `ret_ctrl_t`（§3.18）与返回 CSR 组合输出给出，B 必须提交；③**trap 类 B**（B 自身带异常/中断）——trap 入口按 `vec_off` 向量跳转（§3.18），B 的投机映射由**异常提交路径**撤销（§5.2 `CT` 行① exc 分支），重执行由 `mepc` 返回路径承担。
**回滚期二次冲刷（D3-③，2026-09-24，见 `doc/verify/05` R-076）**：`rollback_busy=1` 期间发生第二次 `flush_apply` 时：①目标更新判据写死**严格更老**——令 `d ≜ (B − B_o) mod 256`：`0 < ((B − B_o) mod 256) < 128`（即 `d∈[1,127]`）⇒ 更新 `B := B_o`（**等价式** `128 < ((B_o − B) mod 256) < 256`；**方向注**：反向式 `0 < ((B_o − B) mod 256) < 128` 系更年轻读数、不可采用）；**`older` 非严格、不得单用**（`older(B_o, B)` 在 `d==0` 时判真，与“同级⇒吸收”相抵——阻-L7-1 根因）；**同级（`B_o==B`）⇒ 无害吸收**（幂等空操作：目标不变、序列不变、尾指针 no-op、重定向照常）；**更年轻（`d∈[129,255]`）⇒ 致命**（防御、构造不可达）；`d==128` 沿终止规则致命（ADR-D5-①，2026-09-24，见 `doc/verify/05` R-080）；②**沿用进行中的弹出序列**（不清栈、不回插、不重启），尾指针按新目标 `B_o` 再截断（§5.2 `S` 行口径）；③前端与重定向照常，取指目标＝最新 `target_real`；④**不得启用 checkpoint 覆盖恢复**（`rollback_busy=1` 期间一律走逐条路径）——判据（保守充分）：目标快照点之后**已发生任何逐条回滚归还**即禁用 cp 覆盖（部分归还与 `FL_ck` 区间重叠 ⇒ 双归还风险）；⑤全程总弹出 ≤ 栈深 ⇒ 收敛不叠加（活性界见本段末公式，≤10 拍）。
**ckpt 槽释放与 `ckpt_pend_v`（附M-B-8② 定案，2026-09-23，见 `doc/verify/05` R-067）**：释放事件三源闭包＝①提交（§5.2 `CT` 行②）②`flush_apply` 生效拍（checkpoint/rollback 两路径统一——checkpoint 路径不再等“回滚完成拍”）③原“回滚完成拍”保留为**兜底等价时刻**（与②先到即释放）。为覆盖②之后 `ckpt_holder_vec` 在途未闭的窗口（ROB 条目作废未及反映），新增 **`ckpt_pend_v`：4 bit 内部寄存器**（每槽 1 bit，`CHECKPOINT_COPIES=4`）——**定义按三项写死（附M-D4-② 定案，2026-09-24，见 `doc/verify/05` R-077）**：**①覆盖窗口**＝**(a) 持有人在途**（`R` 级已分配、`ckpt_holder_vec` 尚不可见；含分配被冲刷作废路径；**该窗口由本寄存器唯一托管**）＋**(b) 释放在途**（释放已发起、闭包未完成）；**②置位**＝该槽 `R` 级分配拍（`needs_ckpt=1` 同拍决定）与释放点火拍；**③清零**＝(i) 首现 `holder==1`（持有转可见，a 闭）；(ii) 自点火拍**次拍**起、首现 `holder==0` 即**当拍清零**（b 闭）——**点火当拍不清零**（留 1 拍防竞争余量）；**分配作废路径闭包**：被杀分配的槽 `holder` 恒 0、两条件均不自发满足——由 §5.2 `CT`③ 同拍补发点火覆盖，点火次拍起即清零（澄-L7-1 定案，2026-09-24，见 `doc/verify/05` R-080）。**“槽可得”统一判据**：`槽 i 可得 ⇔ !ckpt_pend_v[i] && (ckpt_holder_vec[i]==0)`（分配裁决／§7 A6／`spec/04` T-04-3 三读者共用；分配裁决读当拍值、同拍多 lane 按 lane 序）。实现可选 1 bit＋次拍采样或 2 bit 相位编码（行为等价）。**非接口、非 struct 成员、不入 `width_check`**，仅内部状态与监视器采样点。**（建议，编号待 `spec/11` 定稿）**：`flush_apply |=> ckpt_pend_v==0`（冲刷生效后 1 拍内在途释放必闭）；**成立前提（构造性，附M-D4-②）：`ckpt_holder_vec` 对作废的反映 ≤1 拍**（`spec/04` 收口时核对）**；分配作废路径由 `CT`③ 同拍补发点火覆盖（澄-L7-1 定案，2026-09-24，见 `doc/verify/05` R-080）**。

**快照时点（CLR-06 定案；N-01 扩三元）**：checkpoint 数据 = {RAT 整表快照, `SP_ck`, `FL_ck`}，物理采样点两个、语义分界一个（"B 生效后"；D3-① 改，2026-09-24，见 `doc/verify/05` R-076）：
RAT 快照与 `FL_ck` 在 `R` 级按 **lane 序**处理的过程中、本分支 lane 生效后采样（**D3-① 补**：与本节“语义分界（B 生效后）”一致化，见 `doc/verify/05` R-078）（RAT 写与 free-list 分配均按 lane 0→3 顺序生效为本设计定死的实现约束）；
`SP_ck` 在 `S` 级 B **压栈后**采样（D3-① 改，见 `doc/verify/05` R-076）（栈压栈亦按 lane 序）。三者语义一致：都取"同组截至 B（含）已生效"的分界态。

**快照字段的位宽与载体（H-04 补齐；附M-B-5 收敛，2026-09-23）**：`FL_ck[5:0]`——与 free-list 分配指针**同宽**（`PRF_INT_ENTRIES=64`（纵①-F4 统一权威名） ⇒ 6 bit，`spec/00` §4.3）；`SP_ck`——宽度 = `log2(HIST_DEPTH)` = **6 bit**（`HIST_DEPTH` **已定值＝33**（ADR-S2；纵①-F8 补：原“待定”占位作废），`spec/00` §4.3）；快照存储量 = `CHECKPOINT_COPIES × (RAT 整表 + FL_ck + SP_ck) = 4 × (192 + 6 + 6)` = **816 bit**（B-5：公式名取权威名 `CHECKPOINT_COPIES`，原 `CHECKPOINT_NUM` 作废；X4/ISS-003 随 `HIST_DEPTH` 定值**关闭**），归 `spec/04` 容量表与 `spec/00` §4.8。

**栈条目字段的双名绑定（H-04）**：栈条目的 `new_paddr` **即** `rmap_uop_t.rd_paddr`、`new_alloc` **即** `rmap_uop_t.rd_is_new`（均见 §3.5）——同一语义的两个别名，实现必须用**同一根线**接两处；若以为是两个信号各接一份，`new_alloc` 会悬空 ⇒ 逐条回滚时"是否归还"判据失效，N-01 的归还机制随之失效。

深度 = 参数 `HIST_DEPTH` = **33**（ADR-S2 已定值，`spec/00` §4.3；“待定”占位与 X4 关闭——附M-B-5）；**栈满时 `S` 级反压**（压栈点在 `S`，与 BP2 同口径），不得静默丢弃条目。
**双写者仲裁（附B-C8）**：free-list 的两个写者——提交回收与回滚归还——**作用集合不相交**（提交即不可撤销；回滚只针对未提交条目），同一物理号不存在“既被回滚又被提交回收”的路径，故无需同拍仲裁；若出现同拍同号两次归还，属实现缺陷，由 §7 A13 断言兜底。**栈深度推导归 `spec/04`**（ISS-003 未决即污染冻结面，一并记入）。

冲刷发生时 `BP1..BP6` 的 pending 状态**不得**被冲刷改写（反压是资源状态，不是投机状态）；
`BP1` 的 `rob_near_full` 在 ROB 尾指针回退后由组合逻辑重算，**不得打一拍延迟**（`rob_near_full` 定义见 §4 BP1）——
否则刚回退 20 个条目后仍报“满”，白停一拍。**（附M-B-9 定案补：原 `rob_near_full_d` 已删——“打一拍”与“组合重算”不等价；`rob_tail_rollback` 定义为“回退生效拍脉冲”，§7 A4 已改写为重算等价形式；**D3-④ 补（2026-09-24，见 `doc/verify/05` R-076）：`rob_tail_rollback` 为**单拍脉冲、两档一致**（checkpoint/rollback 路径均单脉冲，多拍回滚中仍单脉冲）；`rob_free` 取**生效拍同拍值**；A4 已改**当拍（`##0`）比较**）** 此条列为断言（§7 A4；BLK-14：原写“§8 A4”系引用错位）。
