## 1. 装 MSYS2（复现步骤）

**注意下载源**：`repo.msys2.org` 国内直连仅约 16 KB/s 且会中途断流；`github.com` 直连不可达。
用清华镜像：

```powershell
curl.exe -L --retry 3 -o "$env:TEMP\msys2-install.exe" `
  "https://mirrors.tuna.tsinghua.edu.cn/msys2/distrib/msys2-x86_64-latest.exe"
# 校验：文件大小须为 94016640 字节
```

静默安装到 `D:\msys64`（Qt IFW 语法，免管理员）：

```powershell
Start-Process -FilePath "$env:TEMP\msys2-install.exe" -Wait -NoNewWindow `
  -ArgumentList 'in','--confirm-command','--accept-messages','--root','D:/msys64'
```

换 pacman 源为 TUNA（两份 mirrorlist；用 PowerShell 写，避免 `$repo` 被吞或写成字面反斜杠）：

```powershell
Set-Content -Path 'D:\msys64\etc\pacman.d\mirrorlist.mingw' -Value 'Server = https://mirrors.tuna.tsinghua.edu.cn/msys2/mingw/$repo' -Encoding ascii
Set-Content -Path 'D:\msys64\etc\pacman.d\mirrorlist.msys'  -Value 'Server = https://mirrors.tuna.tsinghua.edu.cn/msys2/msys/$arch' -Encoding ascii
```

## 2. 两套环境（**最容易踩的坑：别混用**）

MSYS2 装完有两个互相独立的运行环境，本项目**两个都要用**：

| 环境 | 性质 | 本项目用它做什么 | 进入方式 |
|---|---|---|---|
| **ucrt64** | 原生 Windows（MinGW-w64 + UCRT） | RISC-V 交叉工具链、Verilator、dtc、原生 gcc | `D:\msys64\ucrt64.exe` |
| **msys** | Cygwin 派生 **POSIX 层**（无 Linux 内核） | git、make、dtc、gcc；**Spike 的编译与运行必须在此** | `D:\msys64\msys2.exe` |

脚本里不弹窗口的调用式（本文档与 `flow.py` 后续按此口径）：

```bat
D:\msys64\usr\bin\env.exe MSYSTEM=UCRT64 D:\msys64\usr\bin\bash.exe -lc "<命令>"
D:\msys64\usr\bin\env.exe MSYSTEM=MSYS   D:\msys64\usr\bin\bash.exe -lc "<命令>"
```

**为什么 Spike 必须在 msys 而不是 ucrt64**：Spike 源码要 `mmap`（`fesvr/elfloader.cc`）、`termios`
（`fesvr/term.cc`、`riscv/interactive.cc`）、`fork`（`riscv/dts.cc`），而 ucrt64 头文件里**没有**
`termios.h`／`sys/mman.h` ⇒ 原生 MinGW 根本编不过。

## 5. Spike（第二个 ISS；自建，无官方 Windows 构建）

### 5.1 取源与配置

`github.com` 直连被封，但 `codeload.github.com` 可达（tar 包直下）：

```bash
mkdir -p /d/tools && cd /d/tools
curl.exe -L -s -o riscv-isa-sim.tar.gz \
  https://codeload.github.com/riscv-software-src/riscv-isa-sim/tar.gz/refs/heads/master
tar -xzf riscv-isa-sim.tar.gz && cd riscv-isa-sim-master
mkdir -p build_msys && cd build_msys
../configure --prefix=/d/tools/spike --without-boost-regex
```

- **`--without-boost-regex` 必须带**：Boost 上游已移除 Regex 库（MSYS2 的 boost 1.92 里只剩 823 字节的
  残留头 `boost/regex.hpp`），不带则 configure 报 `Could not find a version of the Boost::Regex library!`。
- `--enable-commitlog` **不要再带**：2026-09 的 Spike 已把 commit log 默认编入，该选项会变成
  `unrecognized options` 警告（无害但不必要）。

### 5.2 两处机械补丁（详录 ISS-123）

| # | 补丁 | 原因 |
|---|---|---|
| 1 | `addr_t` → `rv_addr_t`（12 个文件，`sed -E 's/\baddr_t\b/rv_addr_t/g'`） | Cygwin 的 `sys/types.h` 与 `machine/types.h` 各 `typedef char *addr_t`，与 Spike `fesvr/memif.h:14` 的 `typedef reg_t addr_t` 撞名 ⇒ 134 条编译错 |
| 2 | `Makefile` 里 `-std=c++2a` → `-std=gnu++2a -D_GNU_SOURCE`，并去掉 `-Werror` | 严格 ANSI 下 Cygwin 隐藏 `strnlen`／`unlinkat`／`renameat`／`readlinkat`／`sigemptyset`／`struct sigaction`（`__POSIX_VISIBLE` 不足） |

两处都只在**标识符名与特性宏**层，不触 trace 路径（`riscv/execute.cc`／`mmu.cc`／`processor.cc` 零改动）。

### 5.3 编译与验收

```bash
make -j16 spike            # 只编 spike 目标：libcustomext.so 链不过（f32_add 未定义），本项目不用 --extension
./spike --help | grep -i log-commits     # 验收判据：须命中 --log-commits
```

### 5.4 **调用时两条硬规矩**

1. **必须带 `--dtb=<file.dtb>`**：Spike 自生成的 DTB 在本机不可用——`riscv/dts.cc:109 dtc_compile()`
   用 `fork()`＋`pipe()` 起外部 `dtc`，MSYS 的 fork 仿真下产物缺 `riscv,isa`，报
   `core (0) has an invalid or missing 'riscv,isa'`。正路是自己编译 DTB 后走 `--dtb=`（该路径
   `sim.cc:141` 用 `ifstream(..., binary)` 直读，实测通过）：

   ```bash
   spike --isa=rv64gc --dump-dts smoke.elf | sed -n '/^\/dts-v1\/;/,$p' > my.dts
   dtc -I dts -O dtb -o my.dtb my.dts
   spike --isa=rv64gc --dtb=my.dtb --log-commits smoke.elf
   ```

2. **`--isa=` 要显式给**（如 `--isa=rv64gc`）：不给时走默认串，配合上面的 DTB 路径易混。

冒烟实测（`sim/run_env_msys2/run.log`）：tiny ELF（`riscv64-unknown-elf-gcc` 编，`tohost` 写 1 停机）
→ `spike_exit=0`，commit log 逐条含 pc ＋ 指令码 ＋ x 寄存器 ＋ 内存写，形如：

```
core   0: 3 0x0000000080000012 (0x00a3b023) mem 0x0000000080000040 0x000000000000002a
```

> **已知限制（ISS-123）**：① `libcustomext.so` 未链 ⇒ 禁 `--extension`；② 必须 `--dtb=`；
> ③ socket 调试口（`-s`）未编入（`HAVE_BOOST_ASIO` 未定义）。三者本项目都用不到。

### 5.5 项目映射版 oracle（`spike-vr1`）与调用封装

**为什么要第二份**：上游 Spike 的编译期常量（`riscv/platform.h`）是 `DRAM_BASE=0x8000_0000`、
`DEFAULT_RSTVEC=0x1000`（boot ROM 占住 `0x1000`）——而本项目 `sw/env/link.ld` 把代码放在 `0x1000`
（`spec/00` §4.1 `RESET_PC`）。直接拿上游那份跑项目 ELF 会报
`Access exception ... Memory address 0x1000 is invalid`。**守住「一份镜像喂两边」（`AGENTS.md` §3.4 坑 2）
的正解＝把 oracle 映射对齐到项目**，而不是另出一份 Spike 版 ELF（那会让两侧 `pc` 不同址、
逐条比对须放宽＝红线 R6）。

- 源码副本：`D:\tools\riscv-isa-sim-vr1`（上游那份 `D:\tools\riscv-isa-sim-master` **原样保留**）。
- 补丁两处（副本内 `riscv/platform.h`）：`#define DRAM_BASE 0x00001000`、
  `#define DEFAULT_RSTVEC 0x90000000`（boot ROM 让位到项目映射之外）；配置/编译同 §5.1~§5.3。
- 运行**必须给内存区域**（Spike 自带的 CLINT `0x2000000` 与默认 2048 MB DRAM 重叠，会报
  `devices at ... overlap`）：`-m0x1000:0x4000,0x20000000:0x1000,0x40000000:0x10000`
  （＝项目映射：代码窗／signature 窗／数据窗）。
- **调用一律走封装**（别手写 spike 命令行）：

```bash
python iss/tools/spike_run.py check                                # 环境探针（--help 命中 log-commits）
python iss/tools/spike_run.py run <elf> --log <log> --csv <csv>    # 默认 --preset project，自动备 DTB
python iss/tools/trace_compare.py <vriss.csv> <spike.csv>          # 逐条比对（列 pc,binary,gpr,csr）
```

- **trace 两端裁切**（确定性规则，锚＝规格而非 Spike 内部）：起点跳过 boot ROM 前导至 `pc==0x1000`；
  终点＝写 `tohost`（`0x4000_0010`）那行**含**在内即停——Spike 分批执行、批边界才轮询 HTIF，
  停机请求后还会多跑一批（实测 5000 条）`write_tohost` 自旋，属停机后噪声。
- **已实测**（2026-09-26 心跳第十六轮**重跑确认**）：`rv64ui-p-{simple,add,slti,jalr,ld}` 与 vriss 侧逐条
  比对 **mismatch=0**（41/470/237/115/435 条；重跑证据 `sim/run_iss_vs_iss/run.log`；首跑见 R-271）。
- **口径已定（ISS-129 → R0 2026-09-26 裁定②）**：ISS-vs-ISS 对手方＝**`--preset project`**，即
  **改过的 oracle（非原版 Spike）**；原版（`--preset upstream`）实测**跑不了项目 ELF**（两条失败已留证
  `sim/run_iss129_upstream/`），故按裁定②把补丁**固化成受版本控制的补丁件**
  `iss/tools/patches/spike-vr1-platform-map.patch`（两处常量，附应用说明）＋**纳入版本指纹**
  `iss/tools/spike_oracles.json`（`spike_run.py` 每次 check/run 逐次核 md5，不符即拒跑）。
  完整口径（含"两侧不一致先核补丁本身"的纪律）＝ **`doc/verify/02` §8**（落点声明见该节）。

## 9. 已知坑（提前规避）

1. **两套环境别混用**：ucrt64 的 gcc 编不出能跑 POSIX 的 Spike；msys 的 gcc 编不出原生 Windows 目标。
   判断当前环境：`echo $MSYSTEM`。
2. **Spike 一律带 `--dtb=`**（§5.4）；否则报 `riscv,isa` 缺失。
3. **Spike 禁 `--extension`**；`-s`（socket 调试口）不可用。
4. **下载源**：`repo.msys2.org`／`github.com` 国内直连不可用或极慢 ⇒ 走清华 TUNA 与 `codeload.github.com`。
5. **口径提醒（ISS-010）**：一期 `MISALIGNED_EN=0`——硬件不支持非对齐访存，**Spike 不得带 `--misaligned`**；
   两侧口径必须一致，否则非对齐激励会伪装成 DUT bug。
6. **ISS 一律文件级解耦**：不使用 DPI-C 把 Spike/ISS 挂进仿真器（可复现性与 ABI 风险），
   只交换落盘文件（`.hex` ＋ trace CSV）。见 `AGENTS.md` §3.4 坑 1。
7. **一份镜像喂两边**：`.bin`/`.hex` 必须同一产物喂 ISS 与 RTL 存储器（`AGENTS.md` §3.4 坑 2）。
8. **PowerShell 不支持 `&&`**：Windows 侧脚本用 `;` 或走 `cmd /c`／MSYS2 bash（`AGENTS.md` §3.4 坑 4）。
