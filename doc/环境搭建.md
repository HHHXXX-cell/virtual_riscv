## 1. 装 WSL2 + Ubuntu 24.04

**以管理员身份**打开 PowerShell：

```powershell
wsl --update
wsl --install -d Ubuntu-24.04
```

- 完成后**重启**一次；重启后从开始菜单启动 Ubuntu，按提示创建**非 root** 用户名/密码。
- 若报虚拟化未开启：进 BIOS 打开 `SVM Mode`（AMD）或 `Intel Virtualization Technology`（Intel），
  再执行 `wsl --install --no-distribution` 然后从 Microsoft Store 装 Ubuntu。
- 验证（普通 PowerShell 即可）：

```powershell
wsl -l -v          # 期望：Ubuntu-24.04   State: Running   VERSION: 2
```

> 必须是 WSL**2**。若显示 VERSION 1：`wsl --set-version Ubuntu-24.04 2`。

## 2. 发行版内基础包

在 Ubuntu 里执行（后续所有步骤都在 Ubuntu 内）：

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y build-essential git cmake wget curl xz-utils \
                    python3-pip device-tree-compiler libfdt-dev zlib1g-dev
```

## 3. RISC-V 裸机工具链（用官方预编译包，不要 apt 凑）

> 知识库《RISC-V芯片BL602开发环境搭建避坑指南》的两条经验直接沿用：
> ①**不要**用包管理器里可能过旧的工具链，直接下预编译版；②解压路径**不得含空格与中文**。

```bash
mkdir -p ~/tools && cd ~/tools
# 打开 https://github.com/riscv-collab/riscv-gnu-toolchain/releases
# 复制最新版里资产名形如 riscv64-elf-ubuntu-24.04-gcc-nightly*.tar.gz 的下载链接：
wget <你复制的链接> -O rv64-elf.tar.gz
mkdir -p ~/riscv && tar -xf rv64-elf.tar.gz -C ~/riscv --strip-components=1
echo 'export PATH=$HOME/riscv/bin:$PATH' >> ~/.bashrc && source ~/.bashrc

riscv64-unknown-elf-gcc --version        # 必须能看到版本号
```

## 4. Spike（第二个 ISS，用于 ISS-vs-ISS 互检）

**关键：必须带 `--enable-commitlog` 编译**，否则没有 commit 级 trace，
`log→CSV→比对/覆盖率` 整条链全断（知识库《riscv-dv 指令序列生成器精读》坑 #2）。

```bash
cd ~/tools
git clone --depth=1 https://github.com/riscv-software-src/riscv-isa-sim.git
cd riscv-isa-sim
mkdir -p build && cd build
../configure --prefix=$HOME/spike --enable-commitlog
make -j"$(nproc)" && make install
echo 'export PATH=$HOME/spike/bin:$PATH' >> ~/.bashrc && source ~/.bashrc

spike --help 2>&1 | grep -i log-commits     # ← 这一条是真正的验收判据
```

> 嫌编译慢可走香山维护的预编译 Spike（`OpenXiangShan/riscv-isa-sim` 的 releases 有 Linux 二进制），
> 但**必须先跑上面这条 grep 确认带 commitlog**，否则等于白装。
> 若 configure 报找不到 dtc/libfdt：回到 §2 补 `device-tree-compiler libfdt-dev`。

## 5. Verilator（高速仿真与性能测试，M8 唯一合法测法）

## 8. 已知的坑（提前规避，都是本项目会踩的）

1. **不要在 `/mnt/d` 下编译 Spike 或跑 Verilator**——跨文件系统 IO 慢数倍。仿真/编译工作目录放
   `~/vr1work`，只把产物（`.bin`/`.hex`/trace CSV）拷回 Windows 侧受控目录。
2. **Windows 盘符在 Ubuntu 里是 `/mnt/d/...`**（知识库 BL602 那篇反复强调的路径转换问题）。
3. **不要用 root 装工具链**，路径统一 `$HOME`，否则后续 `AGENTS.md` §3 的命令全都对不上。
4. **PowerShell 不支持 `&&`**：所有 Windows 侧脚本用 `;` 或走 `cmd /c`（已记 `AGENTS.md` §3.4 坑 4）。
5. **WSL 时钟漂移**会让回归时间戳与覆盖率合并指纹错乱：每轮长跑前 `wsl --shutdown` 一次。
6. **ModelSim DPI-C 走不通**（本机无 C++ 编译器，ISS-006）→ 不要试图用 DPI 把 Spike/ISS 挂进仿真器，
   本项目一律用「trace 落文件 → Python 比对」。
